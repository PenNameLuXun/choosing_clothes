# 分阶段实施计划

## 阶段 0：项目初始化

目标：

- 明确技术路线
- 建立仓库结构
- 搭建基础开发环境

交付物：

- Monorepo 或多应用目录结构
- 前端基础工程
- API 基础工程
- Worker 基础工程
- 文档和开发规范

## 阶段 1：基础 Web 框架

目标：

- 让用户能进入系统并完成基础操作

任务：

1. 搭建 `web`、`api`、`worker`
2. 配置数据库和 Redis
3. 实现用户登录注册
4. 打通对象存储上传
5. 建立基础页面骨架

完成标准：

- 用户可注册登录
- 用户可上传文件
- 数据库和对象存储链路跑通

## 阶段 2：Avatar 系统

目标：

- 用户可创建和保存 3D 身材

任务：

1. 接入基础人体模型
2. 建立体型参数结构
3. 前端身材编辑器
4. Avatar 持久化
5. 3D Viewer 初版

完成标准：

- 用户可调整关键体型参数
- 3D 模型实时响应参数变化
- Avatar 可保存和重新载入

## 阶段 3：Garment 解析系统

目标：

- 用户上传服装图后，系统能识别并准备可试穿资源

任务：

1. 服装上传页
2. 去背景和 mask 生成
3. 服装分类
4. 关键点与轮廓提取
5. 模板资源管理

完成标准：

- 至少支持 3 类服装
- 每件服装都有可用贴图和分类结果

## 阶段 4：Try-on MVP

目标：

- 打通完整试穿链路

任务：

1. 创建 try-on job
2. Worker 处理管线
3. 服装模板与身体拟合
4. 导出预览图和 `glb`
5. 前端任务状态页与结果页

完成标准：

- 上传衣服到查看结果全流程可完成
- 平均生成时间在可接受范围内
- 失败任务可追踪和重试

## 阶段 5：体验增强

目标：

- 提升产品可用性和观感

任务：

1. 更细体型参数
2. 结果页优化
3. 历史记录与收藏
4. 分享链接
5. 更自然的光照与材质

完成标准：

- 用户可重复使用已有 Avatar
- 用户可管理试穿结果
- 页面达到可演示水平

## 阶段 6：质量升级

目标：

- 为后续高质量试穿打基础

任务：

1. 新增更多服装模板
2. 尝试更高质量形变算法
3. 探索布料模拟离线流程
4. 引入姿态切换
5. 建立评估指标

完成标准：

- 支持更多服装类别
- 试穿结果的一致性更好
- 有清晰的下一阶段升级路径

## 建议实施顺序

如果按最稳妥路径推进，建议顺序如下：

1. 先做 `阶段 1`
2. 再做 `阶段 2`
3. 再做 `阶段 3`
4. 然后做 `阶段 4`
5. 最后做 `阶段 5`

也就是先把“人、衣服、任务”三条主链路分别打通，再组合成完整试穿能力。

## 下一步建议

下一步最值得马上开始的是：

1. 初始化仓库结构
2. 搭建 `web + api + worker`
3. 先实现 Avatar 编辑器和 3D Viewer 骨架

原因是 Avatar 系统是试穿体验的底座，越早跑起来，后面越容易验证整条链路。
